\section{Conclusion and Future Work}

ArchSync implements a deterministic bridge between a declared architecture contract and a source-derived TypeScript service graph. In D1, it achieved 1.000 precision, recall, and F1 for aggregate full and changed node and edge detection, classified 20/20 patches, matched 7/7 violation rule sets, localized 11/11 finding-bearing cases to the expected file and line, and reproduced all outputs across 42 executions. P3 replayed those patches as Git diffs and matched 20/20 merge decisions, changed-file sets, and architecture deltas; matched full-scan results in 20/20 cases; hit the base cache on 20/20 repeated checks; preserved 20/20 normalized results; and parsed 57/189 TypeScript file instances. In D2, the frozen v0.1 analyzer produced 18 TP, 4 FP, 2 FN, and 16 TN; provenance-aware v0.2 produced 20 TP, 0 FP, 0 FN, and 20 TN on the same annotated corpus.

These numbers demonstrate that the current contracts, detectors, and Git-diff regression scenarios operate coherently; they do not establish general accuracy or governance effectiveness because the datasets are synthetic and co-evolved with the implementation. ArchSync makes architecture dynamic by reconstructing implementation state continuously, but keeps design changes human-governed: the analyzer never rewrites the approved model, violations block, and evolution requires review. The immediate research priority is an independently curated holdout and a real pull-request pilot on additional TypeScript systems. Later studies should investigate wrapper and dynamic language patterns, scalability, evidence comprehension, approval load, architect decision time, IaC/runtime evidence, and independently evaluated analyzers for additional languages.

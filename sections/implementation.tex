\section{Implementation}

\subsection{Implemented Prototype}

The implementation is divided across three repositories used in this study. \archsyncrepository{archsync-core}{https://github.com/Little-Boy-s-ArchSync/archsync-core} implements Architecture Model version 0.1, JSON Schema and semantic validation, normalized graphs, graph difference, deny/allow/require/require-path semantics, command-line reports, and deterministic Mermaid and draw.io projections. The roadmap called this Phase 1 planning milestone v0.0; model version 0.1 is the first executable contract rather than a change of phase scope. At audit commit \texttt{f7812c4}, its current verification suite contains 114 tests, enforces 100\% statement, branch, function, and line coverage for the deterministic engine, and exercises 17 built-CLI smoke checks. Coverage here is a software-verification measure and is not empirical accuracy evidence.

\archsyncrepository{archsync-guardian}{https://github.com/Little-Boy-s-ArchSync/archsync-guardian} version 0.3 implements Observed Graph and Finding Contract version 0.1 with analyzer implementation version 0.2. The package number differs from the roadmap's planning label v0.2 because v0.2 was used for provenance-aware analyzer hardening before the PR gate; the Phase 3 scope is unchanged. The analyzer traverses TypeScript files, maps component roots, parses syntax trees through the TypeScript Compiler API, resolves explicit literals and selected environment-variable fallbacks, runs HTTP/PostgreSQL/Redis/AMQP detectors, captures evidence, and sorts and deduplicates output. The Phase 3 module invokes Git without a shell, reconstructs base source snapshots, validates or rebuilds graph-cache entries, maps changed paths to components, merges partial observations, compares stable finding identities, and renders human, JSON, Markdown, and GitHub-annotation outputs. Guardian delegates graph difference and rule semantics to Core. The pinned evaluation revision contains 58 tests, enforces 100\% statement, branch, function, and line coverage for the deterministic engine, and exercises 22 built-CLI smoke checks. These counts describe the immutable runtime artifact used for the controlled measurements, not later distribution-hardening revisions or analyzer accuracy on external systems.

\archsyncrepository{archsync-benchmark}{https://github.com/Little-Boy-s-ArchSync/archsync-benchmark} provides the synthetic Order Platform, 20 executable unified-diff patches, the group-authored ground-truth manifest, a 40-signal TypeScript challenge corpus, integrity validation, mutation tests, and evaluation runners. The patches are real executable diffs, but the system, cases, and labels are controlled research artifacts rather than changes sampled from an external project. Phase 2 applies each patch to a fresh temporary copy; Phase 3 initializes that copy as a Git repository, commits the baseline, applies the patch as a working-tree diff, performs cold and warm checks, and runs a separate full scan as an equivalence oracle for the incrementally reconstructed head. Signal annotations bind detector, file, exact line, expected edge, and a required source substring. Its validation libraries are exercised by 55 tests, including dynamically enumerated ground-truth mutations, while process-level validators and evidence verifiers cover the complete executable protocol. \texttt{archsync-mcp} is not used in the experiment.

\subsection{Reproducibility Controls}

The benchmark pins \archsynccommit{Core}{https://github.com/Little-Boy-s-ArchSync/archsync-core}{2affbbb0da859a32b9b9079b4bf718fc7b14993b}{2affbbb0da85} and \archsynccommit{Guardian}{https://github.com/Little-Boy-s-ArchSync/archsync-guardian}{8779bf7965b3bd15f25834f17ca5321c85ae3f43}{8779bf7965b3}. The controlled dataset and runners are available at \archsynccommit{Benchmark}{https://github.com/Little-Boy-s-ArchSync/archsync-benchmark}{24d63ebf2fc3075a1d64f1eaff38cdc0b7f586fb}{24d63ebf2fc3}. These are the runtime artifacts used to generate the reported measurements; later audit and documentation commits do not silently replace them. The end-to-end manifest records SHA-256 values for the architecture model, nine-file baseline tree, and 20-patch set. Phase 3 evidence additionally hashes the Guardian v0.3 package and normalized Git-diff results while recording the cache protocol, incremental scope, environment, and raw timing samples. Its verifier recomputes derived timing statistics and rejects any incremental result that differs from the full-scan oracle or declared architecture delta. Core's Phase 1 evidence binds production source, tests, the complete fixture tree, verification configuration, package metadata, and lockfile. Guardian's Phase 2 and Phase 3 evidence similarly binds implementation and verification source, fixture trees, package metadata, lockfile, and the pinned Core artifact. The challenge evidence separately hashes its signal manifest, architecture, source tree, normalized result, and analyzer package. A frozen v0.1 result remains bound to Guardian commit \texttt{e1cd98956856} and its original package hash.

We executed the complete verification commands on Windows with Node.js 22.16.0 and the repository-declared pnpm 11.16.0 toolchain. Core passed 100/100 tests and 13/13 CLI smoke checks; Guardian passed 58/58 tests and 22/22 CLI smoke checks; the benchmark passed 55/55 validation-library tests at 100\% line, branch, and function coverage, validated all 20 patches and 40 annotated signals, and reproduced the Phase 2, detector, and Phase 3 evidence artifacts plus the frozen baseline provenance. After packaging the pinned Core and Guardian revisions as SHA-256-verified runtime artifacts, GitHub Actions ran the complete gates from clean \texttt{ubuntu-latest} and \texttt{windows-latest} checkouts. The benchmark workflow passed at audit commit \texttt{24d63eb}, the Guardian workflow passed at \texttt{8779bf7}, and the portable Core evidence workflow passed at \texttt{e3d050e} without changing the pinned runtime package.
